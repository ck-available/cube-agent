# ◆ CubeAgent

> **免安装、开源、不需要管理员权限** 的 AI Agent 桌面客户端
> 设计借鉴 OpenAI Codex CLI、DeepSeek Harness、Qoder、Hermes Agent、Claude Code

## ✨ 它和普通聊天客户端的区别

CubeAgent 不只是一个套壳聊天窗口，而是一个**能真正动手的 Agent**：

| 能力 | 说明 | 借鉴来源 |
|---|---|---|
| **Agent Loop** | 模型输出 → 调工具 → 拿结果 → 再决策，多轮直到任务完成（上限 40 步） | DeepSeek Harness agent-loop / Codex |
| **内建工具** | `read` `list_dir` `glob` `grep` `write` `edit` `bash` `todo_write` `task_complete` | Codex / Claude Code |
| **三档权限** | 建议模式（逐次确认）/ 自动模式（写放行、执行确认）/ 全自动（仍限工作区） | Codex approval-policy、Harness 沙箱档位 |
| **工作区沙箱** | 所有文件读写与命令执行都被主进程限制在你选中的目录内，越界直接拒绝 | Harness workspace-write |
| **审批卡片** | 写文件/执行命令前弹卡片：允许一次 / 本次会话总是允许 / 拒绝 | Claude Code / Codex TUI |
| **变更快照与回滚** | 每次写文件自动保存原内容，Diff 卡片可一键回滚，`/undo` 回滚最近一次 | Hermes checkpoints |
| **任务计划面板** | 模型用 `todo_write` 维护清单，右侧实时显示进度 | Codex to-do list |
| **会话轨迹日志** | append-only 事件流：模型看到的一切都能复盘（system/user/assistant/tool/permission/complete） | Harness "Model-visible means logged" |
| **@ 上下文引用** | 输入 `@` 引用工作区文件，自动把文件内容注入消息 | Hermes context references / Cursor |
| **排队发送** | 上一轮没跑完也能继续发消息，自动排队、本轮结束后串行续发 | Claude Code / Cursor / Codex |
| **会话编辑** | 每条消息可复制；用户消息可编辑重发、模型回复可重新生成，均可撤销 | ChatGPT / Claude Code |
| **会话分支** | 消息上「从这里分支」、侧栏分叉按钮、`/branch`；深拷贝隔离，原会话不受影响 | Claude Code `/branch` / Codex fork |
| **斜杠命令** | `/clear` `/model` `/stop` `/queue` `/compact` `/permissions` `/undo` `/rules` `/export` `/help` | Codex / Claude Code |
| **MCP 支持** | 以 stdio 连接任意 MCP 服务器，工具自动挂载给模型使用 | Codex / Qoder / Harness |
| **项目规则** | 自动读取工作区 `AGENTS.md` 作为长期指令，也可在设置里编辑 | Codex AGENTS.md / Claude CLAUDE.md |

基础能力同样齐全：多服务商、流式输出、思考过程折叠、面具（助手预设）、多会话搜索/重命名/删除、Markdown + 代码高亮 + 复制（用户消息 / 模型回复 / 思考过程 / 代码块，带非安全上下文退路）、深浅主题、导出 Markdown、Token 与费用估算、全量数据导入导出。

## 🎨 界面设计

界面按「开发者工作台」而非「聊天软件」来设计，参考了 Codex、Claude Code、Cursor、opencode、Cline 等主流 Agent 的范式：

- **三栏工作台**：左侧功能区与任务列表，中间对话流，右侧详情面板（可一键收起；窄屏自动收起为浮层）。视觉权重靠**表面层级**表达而非宽度：侧栏最弱 → 中栏最强 → 右栏与侧栏同级但可折叠
- **单列消息流，不用气泡**：所有消息共享左边界，靠 `YOU / ASSISTANT` 角色标签 + 图标底色区分。这是 Coding Agent 与通用聊天的关键分野——气泡会把横向空间吃掉 20%，且让折叠的工具卡无法形成垂直阅读节奏。用户消息是左对齐的 `--bg-3` 卡片 + 左侧强调色竖条
- **代码块是重点打磨对象**：文件名头 + 语言标签 + 右上复制按钮 + **行号栏**（CSS counter 生成，不污染 DOM，复制拿到的仍是纯代码），语法高亮对齐 GitHub Dark / Light，注释刻意压暗以控制视觉噪声
- **Diff 有独立 gutter 列**：`+` / `-` 符号单独成列而非拼进行首，所有行的代码左边界才能严格对齐
- **工具调用三段式**：折叠态是 28px 单行摘要（图标 + 工具名 + 路径 + 状态），点击展开参数与完整输出；风险色只保留 2px 左侧色条，不再整卡染色
- **思考过程默认折叠**：一行「思考过程」+ 旋转箭头，展开后是缩进的浅色块。流式期间也不自动展开——否则消息流里会堆一大段灰字
- **左栏功能区**：`新任务 / 搜索 / 技能 / 连接器 / 版本`，工作区选择器带路径省略（保留末级目录名），会话列表可切换 **任务（按时间分组）/ 项目（按工作区分组）** 双视角并显示相对时间；底部工具条用图标 + tooltip，避免三个文字块与列表抢注意力
- **右栏五页签**：计划 / 文件 / **变更（逐行 Diff，可按文件回滚）** / 轨迹 / **版本（Git 分支与未提交改动）**，底部常驻上下文计量面板；页签用下划线式而非填充块（窄栏 5 个页签用填充会互相挤压）
- **Composer 右下角竖排按钮**：与 ChatGPT / Codex 一致。文本框与按钮不再横向平铺，视觉上不再是两个独立控件
- **状态可视化**：工具运行中 / 完成 / 拒绝各有颜色与图标，计划面板用状态圆点区分待办、进行中、已完成
- **层级纪律**：背景严格收敛为 5 级（`bg-0` → `bg-4`）、边框 3 级、文本 4 级。超过这个数量就会出现「层级疲劳」，视觉上灰扑扑一片
- **克制的动效**：统一 110–240ms（Agent 输出一直在流，长动画造成拖影感），只动 `transform` / `opacity`；尊重系统「减少动态效果」偏好
- **完整的深浅双主题**：语义化设计令牌，默认深色。浅色下浅底配浅分隔线会糊成一片，所以主区用纯白、侧栏用灰底，靠底色差而非边框分区
- **可访问性**：图标按钮均带 `aria-label` / `title`，键盘焦点环可见，配色对比度按 AA 标准选取

## 📥 下载使用

有三种用法，**都不需要管理员权限、不需要安装**。

### 方式 A：绿色免安装版（推荐，功能最全）

到 [Releases](../../releases) 下载：

| 文件 | 说明 |
|---|---|
| `CubeAgent-x.x.x-win-x64-portable.exe` | 单文件便携版，双击即用，无需安装 |
| `CubeAgent-x.x.x-win-x64-green.zip` | 绿色解压版，解压后双击 `CubeAgent.exe`，连临时目录都不用 |

### 方式 B：不用 exe，起个本地服务用浏览器

只要机器上有 **Node.js 18+**，一条命令：

```bash
node server/server.js                    # 起服务并自动打开浏览器
node server/server.js --port 7799        # 换端口
node server/server.js --ws D:\my-project # 启动时直接指定项目目录
```

浏览器打开后是**完整功能**，不是阉割版 —— 文件读写、命令执行、MCP 全部可用。
因为它和桌面版共用同一份运行时实现（`electron/runtime.js`），能力完全等价，
包括工作区安全边界（依然禁止 `../` 逃逸）。

- 启动横幅里会打印一个**带随机令牌的地址**，必须从它给出的地址进入（令牌用于防止本机其它网页跨站调用你的文件系统）
- 只监听 `127.0.0.1`，不对局域网暴露
- `Ctrl + C` 停止服务

也可以用 npm：`npm run web`

### 方式 C：只想聊天、不碰本地文件

直接用浏览器打开 `app/index.html`。此时界面与对话可用，Agent 工具会明确提示未连接本地运行时。

### 关于「没有管理员权限能不能用」

**能。** 三代验证：

1. **不写注册表、不装服务、不往 Program Files 落文件** —— 程序只在你自己的目录里读写，这是标准用户权限范围内的事。
2. **智能拦截只发生在两种场景**，CubeAgent 都做了规避：
   - 放在 `C:\Program Files` 这类受保护目录下运行时，Windows 才会要求提权 —— **请把 exe 放在桌面、下载、文档或 D 盘任意普通文件夹**。
   - 未签名的 exe 首次运行可能弹「Windows 已保护你的电脑」——这不是权限问题，点 **更多信息 → 仍要运行** 即可（代码全开源，可自行构建核对）。
3. **Agent 的文件与命令工具也是普通用户权限**，且被限制在所选工作区目录内；无需 sudo / 管理员即可读写你自己的项目。

> 公司电脑完全锁死、连 exe 都不让执行？用**方式 B**：Node 不需要管理员权限，也不需要安装。

## 💬 会话交互：排队、复制、编辑重发

参考 Claude Code / Cursor / Codex / ChatGPT 的做法，这一层决定"用起来顺不顺手"。

### 上一轮没跑完，怎么发新消息

早期实现是 `if (running) return` —— 点了发送，输入框里的字直接消失，什么也没发生。
现在改成 **排队（queue）**：

| 操作 | 行为 |
|---|---|
| 运行中按 Enter / 点「排队发送」 | 消息入队，输入框清空，队列条显示待发消息 |
| 队列条上的「编辑」 | 把这条取回输入框修改，不占用排队位 |
| 队列条上的「删除」/「全部清空」 | 随时撤销还没发出的内容 |
| 本轮结束 | 队列**自动串行续发**（不会并发），发送键恢复成「发送」 |
| 点「停止」/ 按 `Esc` | 中止当前轮，队列继续发（按钮会显示「停止并继续」） |
| `/stop`、`/queue` | 命令行等价操作 |

关键细节：**发送键在运行中永不消失**，只把文案换成「排队发送」——按钮消失会让用户以为回车失灵。
队列按会话隔离，切换任务时自动清空，避免旧任务的消息串到新任务里。

### 复制

| 对象 | 复制的是 |
|---|---|
| 用户消息 | 原文（含 `@` 引用与附件拼接后的完整内容） |
| 模型回复 | 原始 Markdown 源码 |
| 思考过程 | 独立按钮，只复制 reasoning 不掺正文 |
| 代码块 | **只有代码本身**，不含 ``` 围栏与语言标记 |

剪贴板有三级退路：`navigator.clipboard` → `execCommand('copy')` → 留选区提示 `Ctrl+C`。
前两级在**局域网 `http://` 访问**时必然失效（浏览器只在安全上下文暴露 clipboard API），必须有退路。
另外 `execCommand` 在窗口失焦时会**返回 true 却什么都没写**，因此代码会监听 `copy` 事件确认真伪，
宁可提示手动复制，也不谎报「已复制」——用户粘贴出空内容却以为复制好了，比直接报错更糟。

### 编辑重发与重新生成

- **编辑（用户消息）**：点任意一条自己发的消息 → 原文回到输入框 → 其后对话被移除 → 发送后**替换**原提问重发。
  界面顶部常驻「已移除后续 N 条对话 · 撤销」，误点可一键还原整段历史。
- **重新生成（模型回复）**：删掉这条回复及其后的一切，用同样的上下文重新问一次。
- 两者都会保留整段快照而非按索引切片 —— 切片在多轮工具调用场景下极易算错边界。

### 会话分支：换条路走，别弄坏已经通的那条

对应 Claude Code 的 `/branch` 与 Codex CLI 的 fork。想试另一种实现方式，但已经跑通的那条不想动时用：

| 入口 | 效果 |
|---|---|
| 消息上的「从这里分支」 | 复制到这条消息为止，开启新会话，**原会话完全不动** |
| 侧栏会话行上的分支按钮 | 不必先切到该会话，直接分叉 |
| 命令面板 / `/branch` | 分叉整个当前会话 |

- **与「编辑」的区别**：编辑会丢弃后续对话（破坏性），分支是复制（安全）。不确定时用分支。
- 分支会话在侧栏带「分支」标记，悬停可看到它来自哪个会话的第几条消息。
- 计划清单、文件回滚快照、事件轨迹都是**深拷贝**——在分支里继续改文件不会覆盖原会话的回滚点。

## 📊 上下文：实时用量与自动压缩

上下文是 Agent 最容易失控的地方，CubeAgent 把它做成**可见、可控**的一等公民。

### 实时统计

- **进度条常驻输入框上方**，回答过程中**逐字更新**（不是等一轮结束才刷新）
- 鼠标悬停展开明细，按来源拆分：

| 来源 | 说明 |
|---|---|
| 系统提示 | 面具 prompt + 项目规则 + Agent 工具约定 |
| 工具定义 | 所有内置工具的 JSON Schema —— 这是每轮都要重发的**常驻开销** |
| 对话历史 | 用户与助手消息（中文按 ~1.05 字/token，英文按 ~3.6 字符/token 分档估算） |
| 工具结果 | `read` / `grep` / `bash` 的返回内容，往往是大头 |
| @ 引用 | 通过 `@` 或拖拽带入的文件 |

- 右栏常驻面板显示同样的数据，外加步数 / 工具调用 / 耗时 / 输入输出 token / 本次费用
- `/context` 命令输出同样的明细（适合截图或分享）

### 三层防线：折叠 → 约束钉 → 压缩

上下文失控不只是"太长"这一个原因。CubeAgent 用三层机制分别对付三类问题：

**第一层：Microcompaction —— 什么不该进上下文**

超大的工具结果（一条 `bash` 输出可达 12 万字符 ≈ 3-4 万 token）会被**折叠**：原文落到
工作区的 `.cubeagent/toolbox/`，上下文里只留「开头概览 + 结尾热尾 + 归档路径 + 用 `read` 回读」。

关键细节：**归档必须写在工作区内**。放在 `userData` 下的话，`read` 工具的沙箱会拦截，
占位符就成了给模型的假线索 —— 那比不折叠更糟。折叠的条目在界面上可一键展开全文，不丢内容。

**第二层：约束钉 —— 防止"记忆丢失"**

用户在对话里说过的硬性要求（"不要用 X"、"必须用 Y"、"端口是 Z"）极易在长历史里丢失，
模型会"忘记"并违背。CubeAgent 每轮把这类句子**原文重注入**系统提示（成本几十 token）。
这是 Codex CLI 的 Constraint Pinning，其公开数据是重注入后违规率从 30~59% 降到 0%。

只挑「祈使句 + 强约束词」的短消息，最多 8 条 —— 否则噪声和成本都会失控。

**第三层：压缩 —— 最后的兜底**

- **阈值分级**：占用 < 70% 绿色；≥ 70% 黄色提示；≥ 85% 触发自动压缩
- **增量摘要，不是拼接**：旧摘要作为**待更新的草稿**交给模型改写，而不是在后面追加。
  拼接式累积会产出"摘要的摘要"，语义逐轮漂移。模型若无视指令把新旧拼在一起，
  检测到长度异常就**保留原文、放弃本次压缩**
- **摘要质量校验**：模型偶尔会照做历史里的指令（例如末尾挂着"只回复四个字"）而不是写摘要。
  这种摘要写进上下文等于投毒，检测到就放弃压缩
- **保留原文而非粗暴截断**：按 token 预算从后往前保留，并保证不以 `tool` 消息开头
  （切断工具调用配对会导致请求报错）
- 手动触发：`/compact [关注点]`，例如 `/compact 重点看支付模块`

### 🧠 长期记忆：关掉窗口不再归零

没有长期记忆的话，新会话里模型不知道你是谁、这个项目有什么约定。

| 类别 | 作用域 | 例子 |
|---|---|---|
| 用户偏好 / 硬性要求 | 全局，所有项目 | "回答简短一点"、"不要用 TypeScript" |
| 项目约定 / 关键决策 / 踩过的坑 | 当前工作区 | "这个项目统一用 pnpm"、"Windows 构建要加 cross-env" |

- **自动抽取**：每轮对话结束时，只认明确的偏好/约定句式（「以后都…」「统一用…」「不要用…」）
- **手动管理**：设置 → 「长期记忆」可查看、添加、删除、清空当前项目
- **检索方式**：关键词命中 + 类型权重 + 时效衰减，**不需要向量库、零依赖零网络**
- **冲突消解**：新结论与旧结论矛盾时，旧条标记为「已被新结论取代」并退出上下文，
  但**不删除** —— 决策过程可追溯
- **注入有上限**：单次约 1200 tokens，宁缺毋滥。**记忆太多本身也是 context rot**

设计参考 Mem0（事实抽取 → 结构化存储）与 Claude Code 的规则分层，但砍掉了时序知识图这类
需要服务的重量方案 —— 本地场景用不上。

## 🧩 技能与 MCP：它们的真实边界

这两块容易被误解，所以把话说清楚 —— **CubeAgent 没有内置在线插件市场，界面上也不会给你一个假的商店**。

### 技能（SKILL.md 目录约定）

技能就是本地 Markdown 文件，采用 **Claude Code 生态的 `SKILL.md` 约定**，三个目录都会被自动扫描：

| 目录 | 范围 |
|---|---|
| `~/.cubeagent/skills/` | 你的个人技能（可在界面里新建、编辑、删除） |
| `~/.claude/skills/` | **直接复用你已有的 Claude Code 技能**，无需迁移 |
| `<工作区>/.cubeagent/skills/` | 随项目走的团队技能，切工作区即切换 |

结构：`<技能名>/SKILL.md`，首部 frontmatter 写 `name` / `description`（模型据此判断何时调用），正文写做法。
参考 [anthropics/skills](https://github.com/anthropics/skills)。

这是**主流做法** —— Claude Code、opencode 都是纯文件系统扫描，没有 GUI 商店。

### MCP 连接器

MCP 服务由本机以 stdio 方式启动（`npx` / `uvx` 拉起官方 server），无需管理员权限。
界面提供 5 个常用服务**一键填表**（filesystem / GitHub / Postgres / fetch / SQLite），不用对着空表单猜参数。

**关于在线目录**：MCP 官方 registry（`registry.modelcontextprotocol.io`）刻意不提供浏览 UI，
体验层由 Smithery 等第三方聚合站承担；目前只有 Cursor 这类产品内置了真正可浏览的一键安装市场。
CubeAgent 选择把本地配置做扎实，而不是做一个需要外网、经常挂的半成品商店。

## ❓ 常见问题

**Q：API Key 安全吗？**
只存在本机（便携版在 exe 同目录的 `CubeAgent-data`），请求直接从你的电脑发往对应服务商。

**Q：模型不支持工具调用怎么办？**
切回聊天模式即可正常对话；Agent 模式建议用 OpenAI / Claude / Gemini / DeepSeek / GLM / 新版 Kimi / qwen3 等支持 Function Calling 的模型。

**Q：Ollama 连不上？**
Ollama 默认不允许浏览器跨域，设置环境变量 `OLLAMA_ORIGINS=*` 后重启 Ollama。

**Q：为什么要用工作区？**
工作区就是 Agent 的沙箱边界：它只能读改这个目录里的东西，不能碰你的桌面、文档或系统目录。

**Q：不想装 exe，还有别的用法吗？**
有。`npm run web` 起一个本地 HTTP 服务（默认 <http://127.0.0.1:7788>；端口被占用时会提示你换一个），用浏览器打开即可——
这一模式下**本地工具照常可用**（文件读写、glob、搜索、命令执行都走本机服务，受同一套工作区沙箱约束），
只是没有桌面窗口，用系统浏览器当界面。服务默认绑定 127.0.0.1 且带一次性令牌，不会暴露到局域网。

**Q：上下文满了会怎样？**
先用三层机制挡：超大工具结果折叠归档（只留热尾 + 可回读路径）、用户硬性要求每轮重注入（防"记忆丢失"），
最后才在超过窗口 85% 时触发压缩 —— 且压缩是**增量改写**而非无脑拼接。
随时用 `/context` 看各部分占用明细，`/compact` 手动触发，设置里还能管理长期记忆。

**Q：换个会话/关掉窗口，模型会忘记我和项目的事吗？**
不会。偏好类记忆全局生效，项目约定随工作区切换（切项目不会串味）。
对话中出现「以后都…」「统一用…」「不要用…」这类明确表述时自动记入，也可在设置 → 长期记忆里手动管理。
